# StuHelper Storage

StuHelper 的通用存储核心，管理存储实例、准入、容量预占、完整副本、校验、修复和清理。课程资料、文件元数据、用户贡献与奖励由独立模块管理。

首期目标为三份完整副本，两份独立合规副本校验通过后可供业务发布。当前正在实施，受限文件应用层加密、阅读器与真实长期授权验收继续延期。

## 开发

使用 Next 声明的工具链。`make setup` 安装锁定工具，`make check` 检查生成结果、场景、Go、文档与工作流，并强制要求 PostgreSQL。用 `STUHELPER_STORAGE_TEST_DSN` 指定专用测试服务器，或运行 `bash scripts/check-with-postgres.sh` 建立临时集群。

## 边界

每个入口都要求当前授权。运行身份只访问 `storage` schema，迁移使用独立身份。供应商凭据只通过引用解析，数据库、任务、日志与事件不保存密码或令牌。adapter 的返回成功仍需内容校验。

当前存储实例规划上限为 100 个，每次维护最多处理 100 个对象。executor 提供固定 worker、维护扫描与停止恢复。传输大小、并发、带宽、队列和临时磁盘预算均有上限；Linux 私有暂存目录通过进程锁回收上次崩溃残留，服务关闭等待在途操作退出。

并发和带宽限制作用于单个 Service 实例，多个执行进程须分别配置目录并汇总机器预算；数据库任务与容量预占共享同一账本。执行器库可以嵌入 API 或独立入口，真实身份、凭据恢复及生产部署仍由 backend/ops 装配和验收。

行为、实际测试与生产装配缺项见[模块规格](docs/spec/storage.md)。BHpan 驱动已用真实测试账号验证隔离写入、内容读取和永久清理，三份独立账号副本尚未进行真实演练。候选依赖固定到 BHpan 源码提交，不代表已经发行。
