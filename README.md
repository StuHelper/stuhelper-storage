# StuHelper Storage

StuHelper 的通用存储核心，管理存储实例、准入、容量预占、完整副本、校验、修复和清理。课程资料、文件元数据、用户贡献与奖励由独立模块管理。

首期目标为三份完整副本，两份独立合规副本校验通过后可供业务发布。当前正在实施，受限文件应用层加密、阅读器与真实长期授权验收分别按开发记录推进。

## 开发

使用 Next 声明的工具链。`make setup` 安装锁定工具，`make check` 检查生成结果、场景、Go、文档与工作流，并强制要求 PostgreSQL。用 `STUHELPER_STORAGE_TEST_DSN` 指定专用测试服务器，或运行 `bash scripts/check-with-postgres.sh` 建立临时集群。

## 边界

每个入口都要求当前授权。运行身份只访问 `storage` schema，迁移使用独立身份。供应商凭据只通过引用解析，数据库、任务、日志与事件不保存密码或令牌。adapter 的返回成功仍需内容校验。

当前存储实例规划上限为 100 个，每次维护最多处理 100 个对象。executor 提供固定 worker、维护扫描与停止恢复。传输大小、并发、带宽、队列和临时磁盘预算均有上限；Linux 私有暂存目录通过进程锁回收上次崩溃残留，服务关闭等待在途操作退出。

容量刷新与副本巡检保持定期执行，周期由装配配置决定。QuotaValidity 默认五分钟，QuotaRefreshAhead 默认一分钟，VerificationAge 的一半为开始巡检的时间。调整后的有效期用于新样本，过期样本仍拒绝新写，具体范围见模块规格。

并发和带宽限制作用于单个 Service 实例，多个执行进程须分别配置目录并汇总机器预算；数据库任务与容量预占共享同一账本。执行器库可以嵌入 API 或独立入口，真实身份、凭据恢复及生产部署仍由 backend/ops 装配和验收。

行为、实际测试与生产装配缺项见[模块规格](docs/spec/storage.md)。BHpan 驱动已用真实账号验证隔离写入、内容读取和永久清理，backend 另完成三账号副本、重启恢复及会话失效后的凭据重登。本轮真实观察已结束，生产稳定性另行验收；候选依赖固定到 BHpan 源码提交，不代表已经发行。

运维接口使用独立权限，展示容量、健康副本缺口和失败任务，不触发供应商访问。缺失文件的重新复制与容量回收已有数据库测试；供应商会话失效后的凭据重登由 backend 托管层负责。

运维命令支持暂停、恢复暂停、排空、撤销与平台额度调整。任务人工重试检查当前权限、修订和队列预算，保留原写入意图并记录操作者与任务标识。管理页面使用专用 DTO，不读取完整实例或凭据配置。

在线托管接口支持首次接入、原请求恢复和凭据更新。凭据存储与供应商登录由 backend 注入，首次接入不自动开始贡献。托管期限与贡献条件分别管理，接口及浏览器 SDK 仍需实际身份与生产配置接入。
